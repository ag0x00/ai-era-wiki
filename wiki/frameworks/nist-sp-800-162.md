# NIST SP 800-162: Attribute-Based Access Control

[NIST SP 800-162](https://csrc.nist.gov/pubs/sp/800/162/upd2/final) defines attribute-based access control (ABAC) and describes functions used to decide and enforce access. It is a reference for naming roles in an agent authorization path, not an agent-specific control catalogue.

## Publication and scope

NIST published the guide in January 2014 and lists the current text as updated on **2019-08-02**. NIST's [update notice](https://csrc.nist.gov/news/2019/nist-updates-sp-800-162) describes editorial and reference changes. The update was not a new agentic-AI edition or a formal reaffirmation. ABAC evaluates request attributes against policy rules, as the [guide's definition](https://nvlpubs.nist.gov/nistpubs/specialpublications/NIST.SP.800-162.pdf#page=16) explains.

## Functional points

[NIST §2.4.3](https://nvlpubs.nist.gov/nistpubs/specialpublications/NIST.SP.800-162.pdf#page=23) distinguishes four functions. They can run in separate components or share one implementation.

| Function | Responsibility |
|---|---|
| Policy Enforcement Point (PEP) | Receives the access request and enforces the returned decision at the protected object. |
| Policy Decision Point (PDP) | Evaluates decision and management policies against attributes and returns a decision. |
| Policy Information Point (PIP) | Supplies attributes needed for the decision. |
| Policy Administration Point (PAP) | Manages and tests decision and management policies. |

A log collector can supply facts to a PIP, but recording an action after execution does not make it a PEP. A person approving an action supplies a human decision; the PEP still has to hold and enforce the action at its execution boundary.

## Agent application

Applying NIST's general functions to agents is this wiki's architecture choice. The proposed tool call is the access request. The decision inputs are the authenticated agent's task authority, the requested operation, and the protected resource. The PEP must sit on the route the call actually takes, including an orchestrator or alternate autonomy mode. The PDP's permit is useful only while the PEP can prevent a denied call from running.

[[agentic-ai-security-cmm-d2-identity|CMM D2]] tests the principal and task-bound authority behind those inputs. [[agentic-ai-security-cmm-d3-control-least-agency|D3]] tests the decision and enforcement route. [[agentic-ai-security-cmm-d7-observability|D7]] tests the resulting action records. The [[oversight-layer|Oversight Layer]] separates these functions from human approval and observation; NIST SP 800-162 does not assign CMM levels to them.
