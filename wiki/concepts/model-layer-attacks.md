# Model-Layer Attacks

A model-layer attack targets a trained model, its weights, or its inference behavior. The assessment starts with the asset at risk: training data, model function or artifacts, or the correctness of predictions. A private document retrieved into an agent's context is a retrieval exposure, even if the answer is generated by a model. This distinction directs the test to the boundary that can stop it.

## Attack boundary

| Objective | Attacker path | Observable effect |
|---|---|---|
| Training-data reconstruction or disclosure | Query a trained model for attributes or memorized examples | A sensitive training example or attribute appears in output |
| Membership inference | Compare predictions for a candidate record | The attacker can infer whether that record was in the training set |
| Functional model extraction | Query an inference interface and train a substitute | The substitute approximates the target's behavior |
| Direct model theft or modification | Reach weight, configuration, or build artifacts | An exact artifact is copied or a changed artifact is released or run |
| Evasion | Craft an input against the model's decision boundary | The model makes a targeted wrong prediction or decision |

These paths differ in attacker access. A query interface can support training-data inference and functional extraction; direct access to weights supports exact theft or tampering. Evasion can use either interface, and a stolen substitute can help an attacker search offline for transferable inputs. The [OWASP AI Exchange](https://owaspai.org/go/evasion/) separates evasion from model poisoning and describes the surrogate route.

## Source-grounded cases and identifiers

[Tramèr et al.](https://arxiv.org/abs/1609.02943) demonstrated functional extraction of predictive models from query APIs. [Shokri et al.](https://arxiv.org/abs/1610.05820) tested membership inference against model outputs. [Carlini et al.](https://arxiv.org/abs/2012.07805) extracted memorized training sequences from a language model. These are demonstrations of specific models and interfaces, not an expected query count or success rate for a deployed agent.

The current [[mitre-atlas|MITRE ATLAS]] [published technique data](https://github.com/mitre-atlas/atlas-data/blob/main/dist/ATLAS.yaml) distinguishes access from exfiltration:

- AML.T0040 is **AI Model Inference API Access**; AML.T0044 is **Full AI Model Access**.
- AML.T0024 is **Exfiltration via AI Inference API**. Its subtechniques distinguish training-data membership (AML.T0024.000), model inversion (AML.T0024.001), and model extraction (AML.T0024.002).
- AML.T0048 is **External Harms**. AML.T0059 is Erode Dataset Integrity; neither impact technique names model inversion.

The identifier records an adversary technique, not proof that the deployment is vulnerable. Select a test from the actual model route and the asset that can be reached.

## Controls and evidence

- **Training-data exposure:** Minimize sensitive training inputs, document the training-data boundary, and test for memorized output and membership signal. A valid [[differential-privacy|Differential Privacy]] training guarantee can bound the chosen training unit's influence under its stated privacy budget; it does not prove zero leakage of every string.
- **Query-based extraction:** Bind inference access to a principal, limit and monitor cumulative query use, and test for suspicious series without treating volume alone as a determination. Hiding confidence scores can reduce signal for some attacks, but [Tramèr et al.](https://arxiv.org/abs/1609.02943) also extracted models when such scores were omitted.
- **Artifact theft or tampering:** Restrict and log weight access, verify model artifacts and configuration against the approved release, and test that an unauthorized replacement is refused. [OWASP's development-time model-poisoning description](https://owaspai.org/go/devmodelpoison/) includes weight and architecture changes as well as malicious deserialization.
- **Evasion:** Test representative adversarial inputs against the version and task in use, record failure modes, and rerun after a model or preprocessing change. A supplier's general safety result does not establish the agent's route-specific result.

## CMM placement

[[agentic-ai-security-cmm-d8-supply-chain|CMM D8: Engineering and Supply Assurance]] owns model provenance, artifact integrity, assembled-system tests, and release admission. [[agentic-ai-security-cmm-d4-runtime-guardrails|CMM D4: Runtime and Guardrails]] owns applicable in-path checks on prompts and outputs. [[agentic-ai-security-cmm-d6-data-rag|CMM D6: Data, Memory and RAG]] owns retrieved-document entitlement, corpus integrity, and memory state. An answer that discloses a RAG document must be traced through retrieval and output handling; calling it model inversion would conceal the source and the failed authorization path. The current CMM does not assign a universal model-extraction score to every deployment.
