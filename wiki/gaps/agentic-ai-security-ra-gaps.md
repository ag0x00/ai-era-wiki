# Agentic AI Security RA Gaps

Twelve gaps run through the [[agentic-ai-security-reference-architecture|Agentic AI Security Reference Architecture]]. Eleven name a control the architecture asks for that no shipped product delivers or a property most vendors leave undocumented. The twelfth carries a scope decision the architecture has taken and names the plane rows that answer it. They are gaps in the architecture itself rather than in one platform's coverage of it; for a single platform, [[google-cloud-agentic-security-profile|the Google Cloud agentic security profile]] names the planes Google Cloud leaves to an off-stack component.

Items 1 to 11 state what the architecture requires, what ships against it as of September 2026, and where the shipped implementation stops. Item 12 states a scope decision and maps the development-time controls onto the plane rows that carry them. The architecture page cites these items by number.

Two gaps turn on a mechanism a vendor shipped under a heading other than security. Entra Agent ID ships lifecycle workflow templates that can transfer an agent's sponsorship when its sponsor leaves, once deployed, and revoke nothing (gap 7), and the AWS Well-Architected Agentic AI Lens puts consumption anomaly detection in its cost pillar and routes the alert to the team that owns the agent, while the same lens's security pillar detects cross-agent anomalies over message rates and topology and over no cost metric (gap 10). A control filed under governance or cost reaches the operator who reads that pillar and stays invisible to the security review that would look for it.

## Open gaps

### 1. Compartmentalized LLM (CaMeL) reference pattern

Privilege-based data flow control has one documented implementation and no vendor-neutral one. FIDES ships in Microsoft Agent Framework's `agent-framework-core` package from Python 1.3.0 under `agent_framework.security`, carrying an integrity and a confidentiality label on every content item, most-restrictive-wins propagation through tool calls, a policy check before each sink, and a tool-free quarantined model the main model reaches only through a variable reference.[^fides-ra] Microsoft ships it experimental and Python-only, and its documented limitations leave labels opt-in per data source, so a tool nobody labels is governed by the run's default label. Enforcement sits in tool-call middleware rather than in an interpreter over a generated program, which is the [[camel-pattern|CaMeL]] enforcement point and has no maintained implementation: the paper's own code is published as a research artifact its authors disclaim as unmaintained and possibly insecure.[^camel-artifact-ra]

### 2. Cross-tenant MCP server signing

One signed-server path ships, and it carries a distributor's attestation rather than an author's. MCP revision 2026-07-28 states that the identity a server returns in `serverInfo` is self-reported and directs clients not to rest security decisions on it, and the official MCP Registry, in preview, verifies the publisher's DNS or GitHub namespace and delegates code scanning to package registries and downstream aggregators.[^mcp-signing-ra] Docker builds and signs the local servers in its MCP catalog, and `docker mcp gateway run --verify-signatures` checks an image against one Docker-held key compiled into the gateway binary and one Docker-controlled signature repository, failing closed where it finds no signature.[^docker-mcp-sign-ra] A tenant that verifies a server it did not build therefore learns that Docker built it and nothing about who wrote it. No mechanism carries an author's own name-to-binary attestation to a consumer, and the two published designs for one are research proposals.[^mcp-attest-research-ra]

### 3. Multi-agent failure containment

The containment step ships and the detection that would trigger it does not. Copilot Studio's quarantine API marks an agent quarantined and restricts its availability and its interactions, and the Microsoft 365 admin center blocks an agent across the organization.[^ms-agent-quarantine-ra] Cascading failures and rogue agents each have a named conventional-security equivalent now. The Microsoft Agent Governance Toolkit v1.1 answers cascading failures with the circuit-breaker pattern plus rate limiting, and rogue agents with a per-agent behaviour monitor that quarantines an agent exceeding its thresholds, by the toolkit's own assessment of its own patterns.[^agt-crosswalk-ra] No generally available product emits a cross-agent cascade rollup with documented numeric thresholds. Microsoft Defender's agent detections stay in public preview and each one names a single-agent threat class.[^defender-agent-ra] Quarantine is an administrator's action downstream of a flag rather than propagation from a detection. The graph-walk monitors [[multi-agent-runtime-security|Multi-Agent Runtime Security]] tracks (SentinelAgent, TraceAegis) remain at v1 with no released code, and Oktsec supplies per-agent throttling and default-deny inter-agent ACLs with no cascade rollup above them.

### 4. AI-BOM operationalization

Generating an AI-BOM is automated and consuming one enforces nothing. cdxgen ships a dedicated `aibom` command that takes Hugging Face package URLs, Modelfiles and GGUF artifacts, emits CycloneDX 1.7 and submits the result to Dependency-Track, and Anchore Syft catalogues GGUF and SafeTensors components.[^aibom-tooling-ra] Consumption has no gate. The gates in the architecture's [[agentic-ai-security-reference-architecture#5. Data plane|verify-at-load admission row]] check a signature, an attestation or a pinned hash before an artifact loads, and none of them compares an artifact with its AI-BOM. Anchore lists vulnerability scanning of AI artifacts as unsupported, so a pipeline emits a model inventory and matches it against nothing.[^aibom-tooling-ra] The disclosure norm gained a normative anchor without an operational layer, because CISA and the G7 published *Software Bill of Materials for AI — Minimum Elements* on 2026-05-12 and that guidance states that its elements are not mandatory, that implementation detail is outside its scope, and that an SBOM for AI by itself is insufficient until it connects to vulnerability scanning and advisory tooling.[^g7-aisbom-ra] Hugging Face model publishers ship no AI-BOM of their own: a 2026 measurement generated roughly 97,500 artifacts itself from 2,942,466 public Hugging Face model records and scored mean completeness at 54.31 out of 100.[^aibom-completeness-ra] No AI-specific exploitability profile appears in the documents read, since the OWASP CycloneDX authoritative guide to AI/ML-BOM of June 2026 does not mention VEX and the G7 and CISA guidance's nearest element links to external vulnerability databases instead of asserting exploitability.[^aibom-vex-ra] See [[ai-bom|AI-BOM: AI Bill of Materials]].

### 5. Transitive egress constraint on allowlisted destinations

The Egress plane specifies filtering at the agent's own interface and says nothing about what an allowlisted destination can reach. Internal package proxies, artifact caches, and build services routinely hold broad internet access, which turns an allowlist entry into a relay reachable by SSRF ([[openai-hugging-face-agent-incident|OpenAI–Hugging Face incident]], 2026). No listed reference implementation emits evidence that an allowed service is itself constrained, and the one tool that answers the question is a cloud-network analyser the operator runs separately: AWS Network Access Analyzer verifies from configuration whether a resource holds a path to an internet gateway and whether a firewall or NAT gateway sits on every such path, for resources inside that one cloud's VPCs and for nothing else.[^naa-ra] The plane's inter-agent controls assume an A2A protocol, leaving shared writable build infrastructure unmodeled as an agent-to-agent channel. The gap is wider than relaying: a permitted general-purpose host serves content directly, so an allowlist entry for `github.com` or `pypi.org` admits whatever those hosts publish ([[kimi-k3-sandbox-escape|Kimi K3]], 2026). Cataloguing what each allowlisted destination serves is unaddressed by every reference implementation listed, and the enforcement point such a catalogue would need is absent as well: Docker Sandboxes carries host, domain and port granularity in its network rules and no path or method qualifier, although the proxy enforcing them already terminates TLS, and Anthropic documents domain fronting past a hostname-only allow decision as the operator's own residual risk.[^egress-granularity-ra]

### 6. Control initialization order

Every plane specifies *what* is enforced and none specifies *when* enforcement begins relative to the harness's own startup. Agentic coding harnesses read workspace-supplied configuration during startup, and [[gemini-cli-workspace-trust-rce|GHSA-wpqr-6v78-jr5g]] shows that step preceding sandbox initialization, which puts the resulting execution outside all six planes.[^gemini-init] [[claude-code|Claude Code]]'s documentation states the ordering for repository content: a `claude -p` or Agent SDK run in a folder never trusted uses the repository's settings-file hooks, `env` block and `apiKeyHelper` and connects its `.mcp.json` servers without asking, and MCP servers and command hooks run unconstrained on the host, outside the per-command sandbox.[^cc-order-ra] For the other harnesses the wiki tracks, no vendor documentation the wiki holds states the ordering, so the property cannot currently be assessed for those harnesses even where an operator wants to. Two developments narrow the gap without closing it. Gemini CLI's trusted-folders documentation enumerates the workspace-supplied inputs that trust gates — project settings, `.env` files, extensions, MCP connections, memory loading and custom commands — and leaves the position of that check relative to sandbox initialization unstated, and NVIDIA's January 2026 sandboxing guidance records that hooks and MCP initialization functions often run outside the sandbox, answering it with OS-level write protection of configuration paths rather than with an ordering requirement.[^harness-init-ra] Ordering fixes also ship silently: `cursor-agent` moved its worktree setup command behind the workspace-trust prompt in build 2026.07.23-e383d2b with neither an advisory nor a changelog entry, so an operator learns the property retrospectively from third-party disclosure.[^cursor-worktree-ra]

### 7. Identity binding when humans are decommissioned

Ownership reassignment on a leaver event has a reference implementation. Entra Agent ID ships two lifecycle workflow templates that notify managers and cosponsors and can transfer sponsorship when a sponsor changes role or leaves; an administrator must deploy them, and the identity-governance overview names the departing sponsor's manager as the party sponsorship passes to.[^entra-sponsor-ra] Credential rotation and revocation do not travel with the transfer: every disabling, deleting and token-revoking task in that leaver catalogue is scoped to a user object, and disabling an agent stays a sponsor's manual decision in the My Account portal.[^entra-sponsor-ra] Ownership attestation, orphaned-identity detection and automatic revocation are three controls, and the third has no reference implementation: [[okta-for-ai-agents|Okta for AI Agents]], generally available since 2026-04-29, ships shadow-agent discovery, access reviews and an operator-invoked deactivation switch, and the shadow-agent products name a departing employee's agents without revoking them.[^okta-ga-ra] The Cloud Security Alliance puts the unowned population at 8% of enterprise identities, which hold no HR-system ownership linkage after their creator departs.[^csa-nhi-vacuum-ra]

### 8. Shared services above the isolation boundary

Runtime isolation partitions agent execution and leaves every service the agents call undivided. The [[owasp-ai-exchange|OWASP AI Exchange]] names shared inference, credential, and policy services as implicit cross-agent channels that sandboxing does not reach.[^aix-sandbox-ra] The architecture creates two of the three by design: the Control plane concentrates policy in a single decision point, and the Identity plane's credential proxy is one service holding credentials for many agents. Both choices are correct for the reasons those planes give, and both mean an agent's behaviour is observable to, and influenceable through, a component every other agent shares. The observability pipeline is a fourth such component, and the architecture creates it deliberately: one trace backend, one detection stack, and one SIEM serve the whole fleet, and the Exchange separately states that a defensive monitoring agent is part of the attack surface.[^aix-monitoruse-ra] No plane holds a control for any of these four shared components, and no listed reference implementation partitions inference, credential issuance, or policy evaluation per agent. Gap 5 concerns what an allowlisted destination can reach; this gap concerns what a mandatory shared component can carry between agents that never address each other. The Exchange now reaches one of these four components with a control as well as a test: `MONITOR USE` requires the agent action audit trail — identity, action, target, parameters, policy decision, session context, outcome and cross-agent correlation identifiers — in tamper-evident storage the agent cannot modify, and Document 5 supplies the matching adversarial test at the infrastructure layer of an agentic penetration test, which verifies that the agent cannot suppress or alter its own logs.[^aix-monitoruse-ra][^aix-testing-ra] The credential and policy components have the same requirement specified outside the Exchange, in an individual IETF draft on credential brokering for agents: it places the audit trail in a trust boundary separate from both the policy decision point and the credential dispenser, gives neither write access to existing entries, and forbids either from performing the other's function.[^cb4a-ra] The inference endpoint has neither a control nor a test, and the Exchange recommends isolating shared model inference where feasible without naming an implementation.[^aix-sandbox-ra] The policy component stays shared in the one generally available agent policy product, because a policy created on an engine in Policy for Amazon Bedrock AgentCore applies to every gateway associated with that engine.[^agentcore-policy-ra] That test's own four-layer scope, and its relation to the architecture's plane partition, are stated under [[agentic-ai-security-reference-architecture#The six planes|The six planes]].

### 9. Message-fabric integrity below the transport

The Egress plane authenticates agents and blocks direct inter-agent paths; no plane validates the *content* of a structured message against a schema and a delegation scope once the transport is trusted. The Exchange states that peer-agent, tool, and orchestrator messages are untrusted input including inside single-agent tool loops, and that emergent collective behaviour can violate policy even where each agent complies in isolation.[^aix-amsm-ra] Signed delegation tokens with full-chain validation and scope non-expansion are the named control, and single-hop delegation is the part of it that ships: MCP's Enterprise-Managed Authorization extension has the enterprise identity provider mint an identity-assertion grant that the resource's own authorization server validates, and the extension defines one hop with no chained derivation.[^mcp-ema-ra] Full-chain validation with scope non-expansion has no reference implementation in any plane. [[a2a-protocol|A2A]] through v1.0.0 establishes identity at the transport layer and assigns authorization logic to the agent's own implementation, defining no delegation token and no chain validation, and MCP revision 2026-07-28 widened `structuredContent` to any JSON value, leaves the output schema optional, and sets client-side validation of a structured result at SHOULD.[^a2a-authz-ra][^mcp-schema-ra] The chain-verification mechanism itself exists as an individual IETF draft, which requires that a derived token grant no broader authority than its parent and that any enforcement point holding the trust anchor verify the whole chain without a network call.[^attenuating-tokens-ra] See [[agent-message-structure-manipulation|Agent Message Structure Manipulation]].

### 10. Fleet-wide consumption correlation

Per-agent quotas are graded on the Runtime plane and per-agent volume ceilings on the Egress plane; both bound one agent at a time. The Exchange requires monitoring consumption across the fleet for correlated spikes and slow exhaustion attacks, which detects a campaign spread thinly enough that no single agent breaches its own cap.[^aix-limitresources-ra] No plane holds a row for it. One reference implementation specifies the detection and files it under cost: the AWS Well-Architected Agentic AI Lens of June 2026 baselines token consumption, tool-invocation frequency, memory growth and cost per completed task, sets the multi-agent workflow escalation threshold at twice the historical average, and routes the alert to the team that owns the agent.[^awslens-cost-ra] The same lens's security pillar detects coordination anomalies across agents over message rates, workflow frequencies, response latencies, per-pair error rates and graph topology, and over no consumption metric.[^awslens-sec-ra] [[mitre-atlas|MITRE ATLAS]] added an agentic resource consumption sub-technique under cost harvesting in March 2026 and attached no mitigation to it.[^atlas-arc-ra] A denial-of-wallet campaign shows what the omission costs: the service stays available and every response is correct, so an availability monitor stays silent and the only signal is cost per unit of completed work.[^aix-exhaustion-ra]

### 11. Phantom-step detection on the orchestrator

The Control plane's orchestrator-hardening row requires a tamper-evident workflow log held outside orchestrator memory and the reconciliation of executed agent actions against it, which surfaces steps that ran and were never planned.[^aix-oversight-ra] The Observability plane collects traces, behavioural baselines, and per-agent action history, and no row in it compares an execution record against an independent plan record. The comparison is what makes the log tamper-evidence useful: a log the orchestrator alone writes and alone reads records a compromised orchestrator's version of events. The artifact is available off the shelf from a component no plane lists, since a durable-execution engine holds an ordered event history in a service the agent process does not write, and Temporal documents its OpenAI Agents SDK integration as running the agent loop, tool selection and handoffs inside a workflow.[^temporal-agents-ra] The comparison stays absent even there: Temporal's determinism check compares the commands a replay of the workflow code emits against the recorded history, and the same integration runs every model call as an activity outside that replay path, so a step the agent invented replays as recorded fact.[^temporal-ra][^temporal-agents-ra] Plan adherence is a measured quantity in the 2026 literature rather than an enforced one: one study analyses plan compliance across 21,120 agent trajectories on two software-engineering benchmarks, and a second frames self-reported divergence between plan and action as deception.[^plan-divergence-ra]

### 12. Development environment under the Control plane

The Control plane governs the development environment on the same terms as production, under policies differentiated by context. Agentic systems removed the two properties the older separation rested on. A production agent writes and runs code that existed nowhere at deployment, so a production environment is no longer immutable; a development environment reaches production by construction, because an IDE runs on a managed workstation that already holds production access, and a cloud development sandbox already carries access control, network policy and logging. The [[owasp-ai-exchange|OWASP AI Exchange]] reaches the same conclusion from the asset side. Its first stated particularity of the AI development environment is that data protection activities extend from the live system into it, because the model is trained on real sensitive data, and the Exchange grades ISO 27002's separation-of-environments control a partial fit for the same reason: in an AI system the development environment holds the sensitive data that a conventional production environment holds instead.[^aix-devtime-ra]

The five §3.0 particularities no plane accounted for — real sensitive data in place of test data; data, code, configuration and parameters as behaviour-manipulation targets; source code, configuration and parameters as critical intellectual property; external software components running inside the environment with reach to training data and model parameters; and collaborative training across trust boundaries — become policy scoped to a development context rather than a plane of their own.[^aix-devtime-ra] §3.2's three named threats — development-time data leak, direct development-time model leak, and source code/configuration leak — keep the confidentiality impact they carry, and this decision brings them inside the architecture's scope ([OWASP AI Exchange — Sensitive data leak development-time](https://owaspai.org/go/devleak/)).

No plane table gains a row. Four of the Exchange's five §3.0 controls, and three of the high-priority tasks NIST SP 800-218A sets over the same surface, land on rows the six planes already carry; what was missing is that those rows are seldom read against a development environment.[^218a-devenv-ra] `DEV SECURITY` reaches five planes at once, because the Exchange's stated method for it is to add the development assets to the existing security management system: the Egress plane's MCP / A2A / LLM proxy and MCP runtime authorization rows mediate what a development caller reaches, the Runtime plane's input-filtering and content-safety rows hold the guardrails, the Data plane's AI/ML-BOM generation, memory-poisoning-defense and supply-chain-scanning rows hold the assets it names, the Control plane's policy-engine row decides access to them against the attributes the Identity plane supplies, and the Observability plane's behavioural-monitoring and SIEM rows carry its requirement to detect suspicious manipulation of that data, such as a change outside office hours.[^aix-devsecurity-ra] `SEGREGATE DATA` lands on the Data plane. Its requirement — which principal reaches which data — is the one the plane's entitlement row carries, at a different enforcement point: the row scopes a composed answer, and the control partitions the stored areas a development caller works in. The boundary between the five areas it names is enforced at the Egress plane's network-segmentation row where those areas sit on separate networks.[^aix-devcontrols-ra] `CONF COMPUTE` lands on the Runtime plane, on the sandbox-and-containment row and on the Proof-of-Guardrail attestation row, whose reference implementation names the AWS Nitro Enclaves confidential-compute primitive.[^aix-devcontrols-ra] `SUPPLY CHAIN MANAGE` keeps the Data plane's supply-chain-scanning row and reaches the skill and model registry signing row for component authenticity. Of the three 800-218A tasks, continuous monitoring of the development environment lands on the Observability plane's behavioural-monitoring and SIEM rows; protection of training, testing and tuning data on the Data plane, under that same entitlement requirement and on the AI/ML-BOM row that inventories the data; and protection of model weights and configuration parameters on the Data plane's registry-signing row, or on the Runtime plane's containment rows where the concern is weights in use.[^218a-devenv-ra]

`FEDERATED LEARNING` is the one control with no row, and the stage it acts at is the reason. It distributes a training set across organizations so the data need not be collected centrally, which is a decision taken when a model is trained, and the plane tables grade a deployed system.[^aix-devcontrols-ra] Two of its consequences do land. A client that may be malicious supplies poisoned updates, graded at the Data plane's supply-chain-scanning row, and the client-to-aggregator path crosses an organizational boundary, graded at the Egress plane's destination-filtering row. An assessor reading the plane tables now finds the position stated and a row to grade a development caller against in every case but that one.

The AWS Well-Architected Agentic AI Lens is evidence for this shape, and reading its silence as a scope decision mistakes the document type. The Lens runs nine security capabilities for agentic systems and names the development environment in none of them,[^awslens-sec-ra] and it states that it is intended to be used alongside the AWS Well-Architected Framework, so what it omits records the division of labour between the two documents rather than what AWS covers.[^awslens-scope-ra] The base framework covers the surface directly: its Security pillar defines application security as how an organization designs, builds and tests the security properties of the workloads it develops, organizes the guidance around security of the pipeline, security in the pipeline and dependency management, and carries eight best practices from application-security training through automated testing across the release lifecycle, penetration testing, code review, centralized package and dependency services, programmatic deployment, periodic assessment of the pipelines, and security ownership inside workload teams.[^aws-appsec-ra] One control set spanning design, build, deploy and operate, with workload-specific practice layered in a document read beside it, is the arrangement this item adopts.
